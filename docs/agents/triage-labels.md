# Triage labels

Map canonical roles to GitHub issue labels in `sinsenti/TimeTrace`.

| Canonical role | GitHub label | Meaning |
| --- | --- | --- |
| `needs-triage` | `needs-triage` | Maintainer needs to evaluate |
| `needs-info` | `needs-info` | Waiting for more information |
| `ready-for-agent` | `ready-for-agent` | Fully specified, ready for autonomous agent work |
| `ready-for-human` | `ready-for-human` | Requires human implementation |
| `wontfix` | `wontfix` | Will not be actioned |

Apply one triage-role label at a time, removing any previous triage-role label while retaining
unrelated labels. Use `gh issue edit NUMBER --repo sinsenti/TimeTrace --add-label ROLE` and
`--remove-label PREVIOUS_ROLE` as needed. Wayfinding maps/decision tickets use only their
`wayfinder:` labels instead; see `issue-tracker.md`.

## Categories and briefs

Triaged implementation requests carry one category (`bug` or `enhancement`) and one state role.
Wayfinding maps/decisions are the exception above. Historical completed imports need not carry an
active readiness state. Deferred verification uses `enhancement`, not `bug`, until a defect is reproduced.
Follow `triage`'s AI disclaimer on issues/comments produced during triage:

```markdown
> *This was generated by AI during triage.*
```

During `triage`, moving a ticket to `ready-for-agent` or `ready-for-human` includes the durable brief required
by `.agents/skills/triage/AGENT-BRIEF.md`: goal, relevant context, constraints, agreed behavior/testing
seams, and acceptance criteria. Explain the human-only boundary for manual verification.
Other skills use their own publication steps; `to-spec` does not acquire an extra triage-brief gate.

## Implementation completion

Close the GitHub issue with reason `completed` after implementation is delivered and acceptance
criteria have recorded evidence (`gh issue close NUMBER --repo sinsenti/TimeTrace --reason completed`).
List deferred manual acceptance separately; completion does not mean unrun checks passed.
Use the invoked skill's commit/publication/merge steps without an additional local permission gate.
The closed/completed lifecycle state is not a triage role.
For declined work, apply `wontfix`, record the reason, and close with `--reason 'not planned'`.
Historical local tickets may retain their original `Status: completed` notation.
